## 2026-10-01 当前适用范围与批准修订

lingzz 于 2026-10-01 明确批准 A–E，并追加新增功能 TLA 形式化回归、CI 验证及完整 PR 流程要求。本节与[限定范围交付与 DevOps 阶段规则](../00-governance/MLS-DOC-GOV-0008.md)共同限定当前适用内容；下文相冲突的范围、角色、状态和准入表述保留为原基线历史，其余约束继续有效。批准修订与执行验证分别登记。

P3/P4 的浏览器豁免、单轮性能和局部影响复用仅说明那些批次的获批证据边界；支付/审计样本不足、未作 P99/三轮/长期稳定性声明继续保留。新阶段按变更影响复验；新增功能必须有对应 TLA+ 模型或明确抽象映射并执行形式化回归，通过当前 PR 提交的 CI，完成评审、整改及合并流程。模型结论与真实 PostgreSQL/HTTP 结论分别提供。

保留核心并发范围包括同副本竞争、重复支付、关闭与回调竞争、日结与在途写入；与实际数据库提交相关的性质继续用事务集成证据验证。原九场景并发、六浏览器与计时观察属于原全量协议。新增功能的模型、CI、PR 证据必须针对同一候选，不以历史成功批次替代。

## 1. 范围与方法

本设计把已批准需求与验收定义反向映射为系统级测试结构，用于检查总体设计可验证性（GOV-0006 §6.4 工作项 6）。它规定**测什么、在哪种环境测、数据从哪来、结果如何判定**；可执行用例规格（步骤级脚本、断言代码）属 M4 出口。执行时点为 M5/M6，本设计不宣称任何测试已执行。

设计输入：需求基线 v1.0（REV-0002）、场景分析结论（OD-0002/OD-0003，SC-Q1～Q15、C1～C11 已确认并经形式化验证修补）、质量签署候选（`MLS-DEC-0023`~`0026`）。

## 3. 并发与恢复系统场景（设计级）

并发正确性按三层验证：外部行为断言（BR-0039~0048，黑盒）、交错场景（AT-0030/0031/0032/0033，灰盒注入）、机制规则（M4 冲突/重试/恢复规则，白盒）。关键设计约束：

- 并发交错控制与故障注入经**受控测试接口**执行（仅测试环境开放，M4 定义故障注入点）；不通过 UI 时序凑合并发。
- 进程中断恢复场景在业务提交边界注入（SC-Q2/Q5/Q9 的事务范围），恢复后断言无半完成结果、无重复事实、流程可继续。
- 逻辑 T 场景以真实数据库锁等待和受控闸门构造，不用睡眠凑竞态；计划钟点仅触发隔离请求；订单终态吸收以迟到事件注入。
- 每场景同时断言对应审计事件存在（失败审计不随业务回滚丢失）。

## 4. 测试环境与数据规范

- **环境规格 [E]**：单机 4 vCPU / 8 GiB，Compose 全栈（前端、后端、PostgreSQL、观测栈、本地支付模拟器），与生产候选同构（OD-0002 §5）；参数与资源饱和阈值按 `MLS-DEC-0025` 执行。测试执行环境不混入开发热路径。
- **数据库**：真实 PostgreSQL（版本与镜像摘要按 B1-B 固定值），Flyway 迁移后基线数据加载；并发/恢复场景使用独立数据库实例，避免观测栈采样互相污染。
- **数据类别**：专用学习读者（多角色）、书目与副本（覆盖六态）、预约/候补/借阅事务（覆盖状态机全迁移）、罚款与订单（覆盖四态）、模拟器通知（有效/重复/迟到）、审计事件；固定数据集在用例中登记，不复用生产数据。
- **可复现性**：每场景登记数据装载脚本入口、执行参数与判定查询；结果证据含请求时间线、审计导出与（性能类）测量三份数据（应用/数据库/观测）对账（AT-0016 口径）。
- **边界排除**：真实支付网络、真实外部系统、真实模型端点（延期项）不在本设计执行范围；AI 真实端点场景待统一配置建立后补录执行记录。

## 5. AT-0030 转可执行场景（OQ-0027 关闭产物④的 M3 部分）

`MLS-AT-0030` 的并发断言已具备场景化条件：本设计将其拆为 9 个可执行场景（两请求竞争单副本、多请求竞争末副本、队首取消×分配竞争、同幂等键并发提交、展示与提交之间状态变更、到期任务并发扫描、支付通知并发重放、业务提交后中断恢复、重启后一致性核对），每场景绑定注入方式（§3）与断言锚点（BR-0039~0045 逐条）。步骤级规格与断言代码在 M4 可执行用例规格中定稿（OQ-0027 关闭产物④完成时点），追踪经 RA-0014 更新。
