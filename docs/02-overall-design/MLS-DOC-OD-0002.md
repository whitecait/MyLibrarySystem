## 1. 阅读口径

本文是基于已批准需求形成并经 REV-0003 v1.3 批准的总体设计。模块指集中实现一组职责并向调用者提供接口的代码集合；接口同时规定输入、结果、权限、状态约束和失败行为，不仅指 HTTP 路径。框图不表示独立进程、独立数据库或已实现功能。

事实依据以 REV-0002 激活记录为准；RA-0003 §1 仍含 G5 未通过的旧状态声明，本稿不采用其阶段状态，但采用其已纳入基线的业务范围。该来源状态差异保留待受控维护。

实线为调用或明确标注的数据访问；虚线为异步事件流或契约约束，含义在箭头上注明。模块划分、调用组织和物理位置按本文及 MD-0002～0004 执行；需求要求的行为不因分组改变。各图区分逻辑职责、代码组织和运行节点。

Application Layer 是图中容器，容器不接受调用也不拥有业务状态；内部每个用例只依赖本次办理需要的公开接口。鉴权与事务为用例共有约束，不集中到一个“万能业务模块”。各用例组织自身跨模块调用与事务；具体状态只有所属模块能够修改。模块间通过接口协作，不从另一个模块旁路写表。查询组合只读，不能用缓存或展示状态决定提交是否成功。

| 模块           | 自己维护的事实与接口责任                                                                                                     | 关系依据                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 身份与读者     | 账户生命周期、唯一角色与读者资料；提供会话身份和访问判断。罚款、逾期资格由当前业务事实计算，不复制成另一个可独立修改的布尔值 | FR-0002～0005；RA-0008 §2、§7                                                       |
| 书目与阅读内容 | 书目、分类及公开阅读内容关联；不拥有副本借出或预定状态。阅读器交互属于前端，内容读取经公开接口                               | FR-0006、0040、0045                                                                 |
| 流通           | 副本完整六态、预约/候补与借阅事务、绑定关系、续借、普通转人工处理、闭馆与维护后即时分配；对外提供办理动作，不开放任意改状态  | FR-0007～0013、0015～0016、0028、0036～0039、0046；RA-0008 §3～7、§11、§13～16、§20 |
| 罚款与模拟结算 | 罚款金额义务、支付订单与结果、关闭/退款/对账；内部区分罚款账务与支付适配。依据归还结果形成罚款，向流通提供当前未缴事实       | FR-0014、0017～0026；RA-0008 §8～9                                                  |
| 高风险复核     | 保存发起、拒绝/通过和执行关联；不拥有被复核的账户、罚款或流通状态，不能通过通用“改字段”接口生效                              | RA-0008 §7；FR-0004、0012                                                           |
| 查询组合       | 组合书目、流通、身份、结算的可见数据，形成门户、我的业务与馆员到馆统计；冻结的日初计划事实仍由流通维护                       | FR-0001、0008、0039～0043；RA-0008 §16～19                                          |
| AI 助手        | 会话事件、模型调用额度、工具编排及预填草稿；会话日志与操作审计分开，使用会话/消息/草稿标识关联                               | FR-0029～0035；RA-0008 §12                                                          |
| 通知与审计     | 各自维护投递/查询事实；事件重复不得重复产生业务通知。发送结果不触发再次分配或借出                                            | FR-0027、0038、0044；RA-0008 §10、§15、§18                                          |

先合并副本生命周期与流通，是因为预约确认、借出、取消和闭馆都要同时维护事务与副本绑定。书目维护页面仍可发起副本新增/维护，但调用流通接口；页面上的相邻功能不代表由同一个后端模块写入。维护完成与闭馆结算复用同一分配过程，符合现有需求，不拆成两套规则。

### 关键跨模块关系

| 动作           | 调用组织                                         | 一致性要求                                                                                                           |
| -------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 注册           | 注册用例组织身份与读者记录建立                   | 成功时完整建立读者身份，不暴露半成品                                                                                     |
| 借阅/预约/续借 | 用例获取身份及当前结算事实，调用流通判定与执行   | 资格与副本/队列状态在提交时复核；具体锁序、冲突返回及重试归 OQ-0027 详细设计                                             |
| 归还           | 用例组织流通结束/副本迁移、罚款形成、Outbox 记录 | 用户已确认同一事务，失败整体回滚；不能先归还成功再因罚款写入失败永久漏记                                                 |
| 支付结果通知   | 结果处理用例组织订单与罚款结算                   | 有效结果只生效一次；重复、冲突结果不重复结算；不让模拟器直接改业务表                                                     |
| 复核通过       | 复核用例组织复核记录和目标模块受控动作           | 执行前重新校验目标最新状态；拒绝不改变目标。SC-Q9 已确认批准记录、目标变更与待投递事件整体提交或回滚，失败仅保留审计日志 |
| 闭馆           | 触发器调用流通闭馆用例                           | 未到馆→清点→结算，阶段间不插入其他业务事件；隔离与崩溃恢复机制待 DD                                                      |
| 显示检索/日历  | 查询组合读取书目与流通可见结果                   | 可借显示不保证预约成功，允许陈旧范围遵循批准质量要求                                                                     |

两侧以同一份契约为输入。前端不复制业务决策来模拟权威结果，mock 按预置场景返回；后端不依赖前端启动来验证事务。契约源为 DD-0002；工作包责任见 TODO。是否拆分身份/读者或罚款/支付内部包可在 DD 细化，不影响本稿对外职责。

图中 INPORT 表示按用例划分的接口集合，不是所有用例共享一个万能接口。源码依赖箭头指向调用者所依赖的接口；虚线“实现”从 Adapter/实现指向接口，不表示接口反向依赖实现。STORE 只是各模块私有持久化端口的图示分组，不是跨模块共享数据库操作入口。事务绑定到同一连接，由用例确定提交范围；模块不得另开连接破坏跨模块原子性。

| 位置               | 允许的源码依赖                       | 禁止的源码依赖                                | 验证入口                               |
| ------------------ | ------------------------------------ | --------------------------------------------- | -------------------------------------- |
| 应用用例           | 目标模块公开接口、事务与事件登记端口 | 目标模块内部实现、直接 SQL、Spring Controller | 用例契约测试与真实数据库交错测试       |
| 业务模块内部       | 自有规则与持久化端口                 | 他模块内部类型/表、Controller、前端           | 状态迁移/规则测试                      |
| PostgreSQL Adapter | 所实现的端口及 JDBC                  | 业务模块通过反向依赖导入 Adapter              | Testcontainers；替身不证明锁与事务语义 |
| Composition Root   | 各具体实现，仅承担装配               | 业务判定与流程编排                            | 依赖装配和启动测试                     |
| 前端页面/表单      | 请求端口和 UI 状态                   | 后端实现细节、复制权威决策                    | 同一端口切换 HTTP/Mock Adapter         |

接口按真实业务责任与可替换位置设置，不为每个内部类增加一层只转发的接口；当前图给出准入约束，不宣称这些包已实现。

## 4. 进程视图：成功事实与异步投递

```mermaid
sequenceDiagram
    participant U as 用户页面
    participant A as 归还用例
    participant C as 流通模块
    participant F as 罚款模块
    participant DB as PostgreSQL
    participant D as Outbox分发器
    participant E as 审计消费者
    U->>A: 提交具体副本归还
    A->>A: 验证当前身份与权限
    A->>DB: 开始一致事务
    A->>C: 校验在借关系并登记归还和副本状态
    C->>DB: 写流通事实
    A->>F: 按有效归还事实形成逾期罚款
    F->>DB: 写罚款事实
    A->>DB: 写待投递业务事件
    alt 全部成功（RT-D3/RT-D4 判定后整体提交）
        A->>DB: 提交事务
        A-->>U: 返回办理结果
    else 重复归还或对象无效（RT-D1）
        A->>DB: 回滚本次写入
        A->>DB: 独立失败审计（不重复归还/计罚）
        A-->>U: 返回已有结果或明确失败
    else 事实冲突无法自动判定（RT-D2）
        A->>DB: 回滚本次写入
        A-->>U: 转人工处理，不猜测归还成功
    else 业务写入失败（RT-D5）
        A->>DB: 整体回滚
        A-->>U: 明确失败，无半完成结果
    end
    D->>DB: 读取已提交的待投递事件
    D->>E: 投递事件（可能重复）
    E->>DB: 幂等记录审计
```

分支标注对应 OD-0003 §4 的 RT-D 分析行（该节沿用本图作为归还模块时序，并以此图为其时序覆盖声明目标）。此图仅示归还链；它不暗示所有动作都有罚款或到馆通知。未产生业务记录的拒绝判定也必须有审计记录，不能随业务回滚被丢弃。任务和分发器的并行度、互斥、重试以及多消费者投递记录按 DD-0004/0005 执行。

## 6. 场景视图（+1）：AI 预填仍由用户在页面办理

```mermaid
sequenceDiagram
    participant U as 用户
    participant AI as AI助手
    participant Q as 已登记查询接口
    participant P as 当前页面内模态业务表单
    participant B as 业务用例
    U->>AI: 提出权限内的L2操作请求
    AI->>Q: 按当前身份加载可见事实
    Q-->>AI: 查询结果
    AI-->>U: 页面入口卡片与草稿参数（无确认按钮）
    U->>P: 点击对话入口卡片，当前页面弹出模态表单并检查预填
    alt 用户在现行表单提交
        P->>B: 现行请求与会话/消息/草稿关联
        B->>B: 重新鉴权、校验最新事实、执行规则
        B-->>P: 成功或明确未完成
        P-->>U: 展示结果
    else 取消或未提交
        P-->>U: 不产生业务事实
    end
```

入口卡片在对话中；L2 预填和 L3 引导均在当前页面以模态框承载现行业务表单，不导航到新页面。取消模态框不提交业务，现行表单确认仍重新鉴权与校验。资金与高风险等 L3 行为只给页面引导，不进入上述 L2 预填路径；L4 拒绝。AI 不推送办理结果，用户返回对话可继续查询。

| 检查场景       | 需要贯通的模块               | 用于检查草图的关键问题                             |
| -------------- | ---------------------------- | -------------------------------------------------- |
| 登录续行与预约 | 身份、查询、流通             | 目标保留，登录后仍重验最新资格与副本/队列          |
| 自助批量借书   | 前端会话、流通、审计         | 逐册独立成功或失败，清空会话不撤销已借出事实       |
| 归还与罚款     | 流通、罚款、Outbox、审计     | 不重复归还、不漏罚款、不丢关键审计                 |

### 13.1 用户确认的边界

### 13.2 合法订单来源

下表依据已引用的 RA-0008 §5/§8/§9 与 RA-0010 FR-0014/0018/0024/0025/0031，区分产生收费依据、创建支付订单和后续记录。新增场景必须有业务来源，不能仅因技术上存在超时、重试或事件就创建订单。

| 事件/入口                            | 产生的事实                              | 是否创建新支付订单         |
| ------------------------------------ | --------------------------------------- | -------------------------- |
| 馆员办理逾期归还                     | 归还事实与逾期罚款，遵循 SC-Q2 原子提交 | 不自动创建；罚款是支付依据 |
| 读者对本人应结算罚款明确发起模拟支付 | 基于有效罚款建立本地模拟支付订单        | 现有需求明确的建单入口     |
| 超时、查询、重复通知、重试通知       | 日志或既有订单结果核对                  | 不因这些事件另建订单       |
| 关闭订单                             | 已有订单受控终止                        | 不另建支付订单             |
| 馆员对已完成支付申请退款             | 与原支付关联的退款业务记录              | 退款不是新的正向支付订单   |
| 授权角色手动对账                     | 对账记录及差异                          | 不因差异自动新增收费订单   |
| 罚款减免/豁免                        | 高风险复核与获批后的罚款处置            | 不因减免创建支付订单       |
| AI 提供支付页面入口                  | L3 引导，用户到现行页面办理             | AI 不代建订单、不代提交    |
| 遗失/损坏赔偿、借阅押金、预约费用    | 没有当前首版收费来源                    | 不设计此类订单来源         |

现有规范未明确合并多笔罚款支付，本稿不增加该能力。同一罚款同时多个订单已由 SC-Q14 明确禁止。建单与支付结果的持久化边界已按 SC-Q13 分开：建单失败不留订单，支付超时保留既有订单。

## 14. 支付尝试超时、订单到期与建单失败（SC-Q13）

2026-09-11，用户 lingzz 明确：“不产生业务是不产生提交事实，但保留订单供再次支付。除非订单本身也超时，此时建立订单关闭事务。同理，建立订单失败不产生订单事务。”

### 14.1 业务概念与结果

- 支付尝试超时：本次尝试没有可提交的支付结果，不提交支付/罚款结算事实；保留已存在的订单供再次支付，只记录超时日志。不因尝试超时创建另一张支付订单。
- 订单到期：订单自身有效期届满，与单次支付尝试超时不同；触发订单关闭事务。关闭本身须成功提交才形成关闭事实，不能只因计时到期便把关闭操作宣称成功。
- 建单失败：没有订单提交事实，不遗留订单业务记录；失败日志独立保存。
- 支付成功、关闭及退款仍各自遵循授权、当前状态校验和幂等要求。已有成功支付不因迟到的超时计时事件被关闭，也不因重试重复结算。

## 15. 同一罚款的订单独占（SC-Q14）

2026-09-11，用户 lingzz 确认：“同一罚款在一个时间点只能有一个罚款订单，不得同时建立多个订单。直到原订单被释放，才能建立新订单。”

## 16. 第九轮确认：订单释放（SC-Q15）

2026-09-11，用户 lingzz 确认建议：未支付订单只有关闭事务成功提交后才释放占用；支付尝试超时、失败或关闭失败都不释放。读者取消支付通过关闭事务处理，订单自身到期同样须提交关闭。支付成功完成罚款结算，不能再为已结清罚款建单。

关闭事实与占用释放必须共同生效，否则会出现已关闭仍占用或未关闭已放开两种矛盾；此为 SC-Q14/15 的实现不变量，不表示已选择具体数据库结构。

## 17. 总体契约原则（统一外部契约）

本节规定前后端共同契约的总体原则；字段级定义、错误码全表与权限矩阵属 M4 详细设计（DD 工件），此处只冻结原则与命名空间。

- **传输与信封**：REST over HTTPS（部署候选内为反向代理内网），资源路径前缀 `/api/v1`；版本通过路径前缀演进，不做过期版本长期兼容承诺（首版无旧接口兼容负担，RA-0003 §3 排除行）。响应统一信封 `{code, message, data}`；`code` 为机器可读错误码，`message` 为可直接展示的中文文案，`data` 为载荷或 `null`。
- **错误码命名空间**：`MLS-<域>-<序号>`，域＝ID（身份）/CAT（书目）/CIRC（流通）/PAY（结算）/REV（复核）/NTF（通知）/AI（助手）/SYS（系统）。语义分级：参数无效、状态冲突（对应 `MLS-BR-0045` 过期状态不成功）、权限不足、未找到、依赖不可用。同一外部行为只暴露一个稳定错误码，锁或内部重试不外泄。
- **枚举与命名**：枚举值一律英文稳定串（如事务 `MANUAL_HANDLING`、副本 `SHELF_READY`、订单 `OCCUPIED/CLOSED/PAID`）；中文仅用于展示文案。数据库、API 与文档枚举一一对应，不引入只在某一层存在的第三套值。
- **分页、时间与空值**：列表统一游标分页（`limit/cursor`，不承诺全量偏移语义）；时间 ISO-8601 带时区；空集合返回空数组而非 `null`；未提交事实不出现占位对象。
- **幂等与重复**：写操作接受幂等键（请求标识）；同一幂等键重复提交返回首次结果，不产生第二份业务事实（`MLS-BR-0042` 外部口径）。
- **权限呈现**：会话身份决定可见资源；401/403 语义与前端路由守卫一致；越权请求被拒绝并记审计（D2 已验证口径）。
- **AI 卡片动作契约**：L2 入口卡片携带动作类型与预填参数，点击后跳转现行页面表单（`MLS-DEC-0021`）；卡片不是独立提交通道，不新增服务端写接口。
- **契约治理**：契约为前后端共同输入（§3），存放目录与生成方式于分工登记时确定；任何接口变更同步契约、示例与两侧检查，不由单侧私改。

## 18. 系统级状态机汇总与状态所有权

四条业务状态线及其唯一所有者（写入只经所有者接口，§2 原则）：

| 状态线   | 状态集                                                      | 唯一所有者       | 规范来源                                 | 终态                                               |
| -------- | ----------------------------------------------------------- | ---------------- | ---------------------------------------- | -------------------------------------------------- |
| 借阅事务 | 待响应→已确认/人工处理中/候补→借阅中→未借出/已归还/归还异常 | 流通             | RA-0008 §13（TX-1~TX-16）、`MLS-BR-0032` | 未借出、已归还、归还异常（终态封闭 `MLS-BR-0044`） |
| 实体副本 | 待清点→可借阅/已预定/已借出/维护中→已下架                   | 流通             | RA-0008 §14（CP-1~CP-12）、`MLS-BR-0023` | 已下架（不可逆）                                   |
| 罚款订单 | 未建单→占用中→已关闭/已支付                                 | 罚款与模拟结算   | 本稿 §16、`MLS-BR-0047`                  | 已关闭、已支付（终态吸收 PAY-D15）                 |
| 闭馆控制 | 开放→隔离→（逐日补结）→恢复                                 | 流通（闭馆用例） | 本稿 §9、`MLS-BR-0046`                   | 恢复（到达 R）                                     |

闭馆结算调度不是独立实体状态机，而是驱动上述三线迁移的批处理过程（SC-Q5 三阶段整体提交）。所有跨线一致性（归还×罚款×事件、批准×变更×事件、关闭×释放）一律由同一事务承载（SC-Q2/Q9/Q15），禁止跨事务半生效。

## 19. 并发模型与统一锁序（OQ-0027 关闭产物①）

本节为 `MLS-OQ-0027` 延期依据中的关闭产物①（M3 并发模型与状态机 CAS 迁移/统一锁序）。外部行为断言已由 `MLS-BR-0035`/`0039`~`0048` 冻结；本节给出达成这些断言的总体机制模型，字段级与重试参数属 M4 关闭产物②。

- **条件更新（CAS 迁移）**：每个状态迁移实现为对唯一所有者记录的条件更新——`UPDATE ... SET state=新, version=version+1 WHERE id=? AND state=期望 AND version=?`；影响行数为 0 即状态已变化，按 `MLS-BR-0045` 返回明确冲突结果，不重试业务判定本身。终态封闭由迁移白名单保证（无任何迁移以终态为源状态）。
- **统一锁序**：需要同时触碰多个资源的操作按固定全局顺序获取：① 闭馆控制 → ② 书目预约队列（按书目键）→ ③ 借阅事务（按事务键）→ ④ 实体副本（按副本键）→ ⑤ 罚款与订单（按罚款键）→ ⑥ Outbox/通知。同层多个键按字典序；任何实现不得出现逆序获取，杜绝环形等待。
- **建单独占**：同罚款建单采用条件插入/唯一占用约束（SC-Q14/D7~D9），第二个请求条件更新失败即返回已有占用结果，不依赖前端按钮防重。
- **逻辑 T 屏障**：协调器先独立提交停止新许可的 draining 标记；普通写事务在同一连接先取得控制行共享锁并读开放 epoch，重验 draining=false 后才获许可，持有到提交/回滚；隔离事务独占同一行并提交 ISOLATED 与递增 version。独占锁等待已有共享许可结束，提交时刻为 T；普通请求重验 admission 且使用 NOWAIT，不依赖独占行锁等待队列阻止新许可，不排队跨隔离恢复后隐式执行。机制验证见 DD-0004 §4。
- **幂等与效果唯一**：写用例以幂等键去重（`MLS-BR-0042`）；事件投递经 Outbox 至少一次＋消费端幂等（`MLS-BR-0044` 终态封闭为兜底）。
- **等待与重试边界**：锁等待有上限；用户可见路径不做无界自动重试（RS 场景流重读语义，DD 定参数）；后台闭馆重试为有限次固定原业务日（`MLS-BR-0046`）。
- 该模型的可执行冲突/重试/恢复规则（含异常与冲突结果、重试上限、恢复行为）与事务边界在 M4 详细设计冻结（关闭产物②），登记预留决策 `MLS-DEC-0008` 于彼时启用。

## 21. AI 模型服务端点：验证延期与决策登记

用户配置的云端 OpenAI 兼容端点 https://api.deepseek.com/、模型 deepseek-flash 已有实测：默认 thinking 模式 5/6 通过，强制函数选择 S3 返回 HTTP 400，原因是“Thinking mode does not support this tool_choice”。显式 `thinking={type:disabled}` 的独立候选配置六项全通过，严格工具调用断言未放宽，原保存配置未修改。
