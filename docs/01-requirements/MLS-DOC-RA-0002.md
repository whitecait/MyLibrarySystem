| 权威性质 | 需求分析工件的导航入口；不单独构成已批准需求基线 |

## 当前状态

当前处于需求编制中，G5 未通过。本文档及其导航工件均不能被解释为最终需求基线；只有经过正式评审并由基线记录明确批准的工件，才可成为下一阶段输入。

## 阅读顺序

1. [需求分析阶段工程化设计](MLS-DOC-RA-0001.md)：已批准的阶段组织、边界与工作基线。
2. [系统需求主规格](MLS-DOC-RA-0003.md)：目标、范围、约束和专题入口的受控汇总。
3. `requirements/`：范围、参与者、流程、需求、规则、信息、质量、术语和 Open 问题专题工件。
4. `acceptance/`：验收策略、验收用例和实际执行报告；执行报告不得由计划或用例替代。
5. `reviews/`：评审清单和需求基线记录；G5 结论必须由这里的批准证据支持。

## 任务索引

| 任务  | 内容                                                   |
| ----- | ------------------------------------------------------ |
| RA-00 | 恢复 `/docs` 版本控制，建立文档治理、编号和变更规则    |
| RA-01 | 归档全部旧文档并标记为非权威                           |
| RA-02 | 建立代码复用台账，区分直接复用、重构复用和弃用重写     |

| RA-06 | 建立新术语表，禁用旧拼音 API 和旧字段术语              |
| RA-07 | 描述核心业务流程及其替代、异常流程                     |
| RA-08 | 建立系统级用例                                         |
| RA-09 | 编写原子化功能需求                                     |
| RA-10 | 独立登记业务规则                                       |

| RA-12 | 定义可量化非功能需求                                   |

| RA-14 | 建立“目标 → 用例 → 需求 → 验收条件 → 验收用例”双向追踪 |
| RA-15 | 完成评审、关闭关键问题并建立需求基线                   |
