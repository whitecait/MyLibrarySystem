## 1. 参与者术语

| 术语           | 规范定义                                                                   | 区别                                                                                                   |
| -------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 访客           | 可公开检索馆藏并可发起自助注册、但尚未以读者身份参与受限业务的公众访问者。 | 注册成功后成为读者；访客不等同于已注册账户。                                                           |
| 读者           | 已注册并可使用读者业务能力的参与者。                                       | 与访客相比具有与自身流通、罚款和续借有关的业务身份；不承担馆员办理职责。                               |
| 馆员           | 负责读者、馆藏和日常流通办理，并在授权边界内处理人工例外的业务参与者。     | 馆员履行日常馆务职责，不自动拥有系统管理员的高风险复核职责。                                           |
| 系统管理员     | 负责系统级账户与权限管理、高权限复核及审计监督的参与者。                   | 与馆员的日常办理职责不同；具体高风险复核范围仍为 Open。                                                |
| 本地支付模拟器 | 完整验收对象中的受控本地模拟参与方，用于产生可控支付结果和异常场景。       | 不是支付平台、官方沙箱或真实外部网络服务；不连接真实支付网络，不保存真实付款信息，不产生真实资金交易。 |

## 2. 馆藏与流通术语

| 术语     | 规范定义                                                                 | 区别                                                                       |
| -------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 书目     | 对同一出版或作品层面的馆藏描述，可关联多册实体副本。                     | 书目用于描述和检索，不是被具体借出的单册对象。                             |
| 实体副本 | 图书馆实际持有并可具有独立流通状态的一册馆藏。                           | 多册实体副本可属于同一书目；借阅和归还针对具体实体副本。                   |
| 流通记录 | 记录具体实体副本在借阅、归还、续借及相关处理中的业务事实和变化。         | 是跨越流通活动的可追溯业务记录，不等同于某一次借阅动作。                   |
| 借阅     | 由馆员发起，使符合条件的具体实体副本交由读者在获准期限内使用的业务办理。 | 借阅创建读者与具体副本的当前流通关系；与续借和归还不同。                   |
| 归还     | 由馆员发起，确认读者交回具体实体副本并结束相应在借流通关系的业务办理。   | 归还结束借阅；不等同于取消借阅或续借。                                     |
| 续借     | 在现有借阅关系未结束时延长获准使用期限的业务办理，首版由读者自助发起。   | 续借不更换借阅对象，也不等同于先归还再借阅。                               |
| 逾期     | 具体实体副本在应还期限后仍未完成有效归还的业务状态。                     | 逾期描述时间边界后的流通事实；罚款是可能由逾期产生的金额义务，二者不等同。 |

## 3. 罚款与模拟支付术语

| 术语     | 规范定义                                                                   | 区别                                                             |
| -------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 罚款     | 按已批准业务规则形成、与读者相关的应缴金额义务。                           | 罚款是业务义务；支付订单是为处理该义务而形成的模拟支付业务对象。 |
| 支付订单 | 为演示罚款支付闭环而建立、可被查询、关闭、退款和对账的模拟支付业务对象。   | 只承载模拟支付流程，不代表真实平台订单或真实资金。               |
| 退款     | 对已完成的模拟支付结果发起反向处理的业务动作。                             | 只改变本地模拟业务结果，不触发真实资金返还。                     |
| 日终对账 | 在约定业务周期结束时核对系统与本地支付模拟器所记录模拟支付结果的业务活动。 | 对账用于识别差异，不等同于付款、退款或审计事件本身。             |

## 4. 判定、例外与审计术语

| 术语     | 规范定义                                                                                 | 区别                                                                  |
| -------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 自动判定 | 系统依据已批准业务规则，对业务请求形成自动通过、转人工或自动拒绝结果的处理。             | 自动判定只执行已批准规则，不得用未关闭 Open 问题中的假设代替规则。    |
| 边界项   | 无法按明确规则直接完成正常自动处理，因临界、冲突、异常或风险条件需要人工判断的业务事项。 | 边界项是待处理事项；人工例外是授权人员对其作出的受控处理。            |
| 人工例外 | 授权人员对边界项作出的、偏离原自动判定或正常处理路径的受控业务处理。                     | 必须记录原判定、原因、说明、操作人员和时间；高风险复核范围仍为 Open。 |
| 审计事件 | 对需追责的业务动作、判定或例外所形成的可追溯事实。                                       | 审计事件用于说明谁在何时基于何种原因做了什么，不等同于一般业务状态。  |

## 5. 工程治理术语

| 术语         | 规范定义                                                                 | 区别                                                            |
| ------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------- |
| 需求基线     | 经正式评审批准、具有明确版本、范围、批准人和遗留问题处置记录的需求集合。 | 当前需求基线尚未建立；阶段设计 `v1.0` 不是最终需求基线 `v1.0`。 |
| 验收用例     | 将已批准需求转化为用户可观察、可重复和可判定场景的验收定义。             | 是执行前的定义，不是实际执行结果。                              |
| 验收执行报告 | 只登记实际执行结果、证据和缺陷的记录。                                   | 没有执行证据时状态只能是“尚未执行”，不能由验收用例或计划替代。  |

## 6. 废弃术语与兼容禁令

- 旧拼音 API 名称只可在明确标注的历史证据中出现，不能成为当前契约。
- 旧字段和旧数据库模型不进入新需求，不建立别名或迁移要求。
- “阶段设计 `v1.0`”与“最终需求基线 `v1.0`”是两个不同对象；前者批准工作方式与首轮边界，后者只有在 G5 正式批准后才成立。
- “验收用例”不是“验收执行报告”；没有执行证据时状态只能是“尚未执行”。

## 7. 语言与术语一致性规则

- 用户界面、用户可见提示、需求与验收文档以简体中文为主。
- 同一概念在文档、界面、验收证据和审计结果中使用统一中文术语；必要英文技术词可在首次出现时于括号内保留原文。
- 角色、状态、错误、成功、处理中和拒绝等用户可见状态不得只显示英文代码或内部标识。
- 源代码标识符、日志字段和协议名称可用英文，但面向用户的含义必须有中文解释或映射。
