## 1. 参与者术语

| 术语            | 规范定义                                                                                | 区别                                                                                                   |
| --------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 访客            | 可公开检索馆藏并可发起自助注册、但尚未以读者身份参与受限业务的公众访问者。              | 注册成功后成为读者；访客不等同于已注册账户。                                                           |
| 读者            | 已注册并可使用读者业务能力的参与者。                                                    | 与访客相比具有与自身流通、罚款和续借有关的业务身份；不承担馆员办理职责。                               |
| 馆员            | 负责读者、馆藏和日常流通办理，并在授权边界内处理人工例外的业务参与者。                  | 馆员履行日常馆务职责，不自动拥有系统管理员的高风险复核职责。                                           |
| 系统管理员      | 负责系统级账户与权限管理、高权限复核及审计监督的参与者。                                | 与馆员的日常办理职责不同；具体高风险复核范围仍为 Open。                                                |
| 本地支付模拟器  | 完整验收对象中的受控本地模拟参与方，用于产生可控支付结果和异常场景。                    | 不是支付平台、官方沙箱或真实外部网络服务；不连接真实支付网络，不保存真实付款信息，不产生真实资金交易。 |
| AI 模型服务端点 | 完整验收对象中经由端点接口接入的受控模型服务组件，兼容本地模型部署与云端 API 两种形态。 | 不是业务参与者，不拥有独立系统身份；AI 助手行为以当前用户身份与权限运行，形态选择属设计决策。          |

## 2. 馆藏与流通术语

| 术语     | 规范定义                                                                 | 区别                                                                       |
| -------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 书目     | 对同一出版或作品层面的馆藏描述，可关联多册实体副本。                     | 书目用于描述和检索，不是被具体借出的单册对象。                             |
| 实体副本 | 图书馆实际持有并可具有独立流通状态的一册馆藏。                           | 多册实体副本可属于同一书目；借阅和归还针对具体实体副本。                   |
| 流通记录 | 记录具体实体副本在借阅、归还、续借及相关处理中的业务事实和变化。         | 是跨越流通活动的可追溯业务记录，不等同于某一次借阅动作。                   |
| 借阅     | 由馆员发起，使符合条件的具体实体副本交由读者在获准期限内使用的业务办理。 | 借阅创建读者与具体副本的当前流通关系；与续借和归还不同。                   |
| 归还     | 由馆员发起，确认读者交回具体实体副本并结束相应在借流通关系的业务办理。   | 归还结束借阅；不等同于取消借阅或续借。                                     |
| 续借     | 在现有借阅关系未结束时延长获准使用期限的业务办理，首版由读者自助发起。   | 续借不更换借阅对象，也不等同于先归还再借阅。                               |
| 逾期     | 具体实体副本在应还期限后仍未完成有效归还的业务状态。                     | 逾期描述时间边界后的流通事实；罚款是可能由逾期产生的金额义务，二者不等同。 |

| 取书时段 | 预约创建时必须填写的预约当日取书时间区间，用于备书需求模拟与分时段到馆统计。 | 不作状态守卫：读者于预约当日提前、准时或延后到台取书均不因时段被拒。 |
| 计划到馆人数 | 日初（上一开馆日闭馆结算完成后）预约日期＝当日且`已确认`的预约读者人数，日初冻结。 | 不含候补读者；日内新增确认与临时取消均不改写日初计划。 |
| 尚未到馆人数 | 当前预约日期＝当日、事务`已确认`且尚未到馆的读者人数；到馆以到台触发取书借出校验为认定事实。 | 括号内为当日全部确认预约均已临时取消的读者人数；部分取消的读者仍计入尚未到馆。 |
| 今日借阅人数 | 当日完成借出读者的互斥分组计数：主数为完成过预约借阅的读者，括号为仅完成线下借阅的读者。 | 同一读者多笔借阅只计入一组；跨日人工放行计入实际完成借出当日。 |
| 明日预计到馆人数 | 次一开馆日`已确认`预约读者与预计当日闭馆结算可兑现的候补读者并集的去重人数。 | 括号为仅因候补计入（尚无次日确认预约）的读者；不含次日现场借阅预测。 |

## 3. 罚款与模拟支付术语

| 术语     | 规范定义                                                                   | 区别                                                             |
| -------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 罚款     | 按已批准业务规则形成、与读者相关的应缴金额义务。                           | 罚款是业务义务；支付订单是为处理该义务而形成的模拟支付业务对象。 |
| 支付订单 | 为演示罚款支付闭环而建立、可被查询、关闭、退款和对账的模拟支付业务对象。   | 只承载模拟支付流程，不代表真实平台订单或真实资金。               |
| 退款     | 对已完成的模拟支付结果发起反向处理的业务动作。                             | 只改变本地模拟业务结果，不触发真实资金返还。                     |
| 日终对账 | 在约定业务周期结束时核对系统与本地支付模拟器所记录模拟支付结果的业务活动。 | 对账用于识别差异，不等同于付款、退款或审计事件本身。             |

## 4. 判定、例外与审计术语

| 术语     | 规范定义                                                                                 | 区别                                                                  |
| -------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 自动判定 | 系统依据已批准业务规则，对业务请求形成自动通过、转人工或自动拒绝结果的处理。             | 自动判定只执行已批准规则，不得用未关闭 Open 问题中的假设代替规则。    |
| 边界项   | 无法按明确规则直接完成正常自动处理，因临界、冲突、异常或风险条件需要人工判断的业务事项。 | 边界项是待处理事项；人工例外是授权人员对其作出的受控处理。            |
| 人工例外 | 授权人员对边界项作出的、偏离原自动判定或正常处理路径的受控业务处理。                     | 必须记录原判定、原因、说明、操作人员和时间；高风险复核范围仍为 Open。 |
| 审计事件 | 对需追责的业务动作、判定或例外所形成的可追溯事实。                                       | 审计事件用于说明谁在何时基于何种原因做了什么，不等同于一般业务状态。  |

## 5. 读者门户术语

| 术语             | 规范定义                                                                                                                     | 区别                                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 书目级可借状态   | 公开门户按书目展示的可用性标签：书目下至少一个实体副本为`可借阅`时显示`可借`，否则显示`不可借`。                             | 仅为展示口径，不代表提交请求必然获准；不显示实体副本数量、编号、位置及不可借的内部原因。           |
| 保证类型         | 预约事务成立时读者获得的保证类别：直接确认（已绑定`已预定`副本）或候补（队列等待、无副本绑定）。                             | 候补不做其他保证，可用时经结算分配转为直接确认；两类状态在事务详情与日历中可区分。                 |
| 预约日历         | 读者页按预约日期展示书目保证状态的日历视图，以颜色区分可直接确认、需要候补与不可预约。                                       | 呈现口径，不替代提交时的入口判定与最新状态校验；同一书目同一日期正常只呈现一种保证状态。           |
| 登录续行         | 未登录用户触发预约或本人事务操作时打开登录模态框、登录成功后继续原操作的交互口径。                                           | 续行请求仍按现行身份、资格与状态规则判定，不因续行获得豁免；模态框固定提示无法登录时线下办理。     |
| 我的业务         | 读者查看本人事务的统一页面，包含当前借阅、预约与候补、历史记录三个分页页签。                                                 | 仅呈现本人业务，不提供他人事务视图；详情含状态、保证类型、预约日期与时段、通知记录和状态时间轴。   |
| 通知 Banner      | 读者页展示排序最高的未读业务通知的站内横幅区域，未读通知按关联预约日期临近程度排序（同日多条不另设先后）、到馆与无需到馆通知对同一预约事务互斥，多条未读时显示`另有 N 条`并以卡片堆叠呈现，点击进入事务详情。 | 站内呈现载体之一；系统同时保留模拟短信或邮件发送记录，不接入真实短信或邮件通道。                   |
| 在线阅读器       | 图书详情子页面中公开的图书内容阅读组件，提供目录、翻页、页码跳转、缩放、全屏与书内搜索。                                     | 对未登录用户公开；属馆藏图书内容的阅读能力，不构成电子资源管理。                                   |
| 自助借阅会话     | 自助借阅中心以扫描读者证建立、连续扫描多册图书、分别校验、确认结果后清空的临时办理载体。                                     | 批次失败项仅在会话内即时呈现、不留持久事务记录（仅判定审计）；会话清空后不残留办理载体。           |

## 6. AI 助手术语

| 术语                     | 规范定义                                                                                          | 区别                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| AI 助手                  | 内嵌于业务系统、以当前会话角色（访客、读者、馆员或系统管理员）的权限提供业务问答和受确认辅助操作的对话式组件。 | 与外挂聊天界面不同：它与业务系统共用同一套数据、业务规则和权限体系；不是业务参与者。 |
| 会话角色                 | 发起 AI 交互的当前身份所属角色：访客、读者、馆员或系统管理员。                                    | 决定 AI 可用问答域、可起草操作与参与级别上限；账户采用一账户一角色，访客为未登录会话角色。 |
| 工具调用（Tool Calling） | AI 助手以结构化参数调用系统登记工具，以获取业务事实或生成操作预填内容的行为。                     | 是 AI 验收口径的主要判定对象；AI 自然语言回复内容不作为业务事实来源或验收判定依据。  |
| 微页面编排动作           | AI 工具调用的登记对象：打开指定页面或页面组件，并注入允许范围内的参数与引导文本的动作。           | 微页面内的数据加载与提交一律走系统现行接口与校验；AI 不新增数据通道。                |
| AI 参与级别              | AI 助手对单项行为参与的深度分级：L1 查询返回、L2 起草确认、L3 页面引导、L4 拒绝。                 | 分级属性为行为与对象的组合：只读查询属 L1，修改类引导属 L3；各级可用范围按角色配置矩阵登记。 |
| 页面入口卡片             | AI 在 L1/L2/L3 级交互中向用户提供的可点击跳转入口：L1 供跳转查看详情，L2 携带操作预填参数（卡片不含确认按钮），L3 仅含占位引导文本。                               | 跳转均由用户主动点击触发，AI 不直接弹出页面；L2 的预填参数经跳转注入现行页面表单，L3 不含 AI 预填业务值。 |
| AI 调用额度池            | 限制 AI 模型服务调用频度的配置化额度机制：访客全体共享一个全局池，登录用户按账户限额，并含单条用户消息的最大模型调用轮数。                                        | 目的是防止 AI 资源被恶意占用；与数据可见范围边界解耦；额度按模型调用计数、成功响应后扣减，失败与超时不计；超额请求被明确告知并留痕，不计模型调用。 |
| 受确认辅助操作           | AI 生成操作预填内容并以页面入口卡片呈现，用户点击跳转后预填参数注入现行页面表单，经用户在现行页面确认提交且完整通过前后端校验后按现行流程执行的业务办理方式。 | 与 AI 自主执行业务变更不同；业务事实仍由现行自动判定和人工处理形成；用户未提交不产生业务事实。           |
| AI 会话日志              | 记录参与者与 AI 助手交互事件的留存业务对象，按事件逐条记录（用户消息、模型请求/响应、工具调用/结果、草稿产出与暂停、拒绝、额度事件各一条）。                      | 与 AI 操作日志分别留存，以会话标识＋消息标识＋草稿标识关联；按业务记录口径永久保留。                     |
| AI 操作日志              | 记录经用户确认执行的 AI 起草操作及其业务结果的留存业务对象。                                      | 以会话标识＋消息标识＋草稿标识关联会话日志、业务事实和审计事件；未经提交的预填不产生业务事实。           |

## 7. 工程治理术语

| 术语         | 规范定义                                                                 | 区别                                                            |
| ------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------- |
| 需求基线     | 经正式评审批准、具有明确版本、范围、批准人和遗留问题处置记录的需求集合。 | 当前需求基线尚未建立；阶段设计 `v1.0` 不是最终需求基线 `v1.0`。 |
| 验收用例     | 将已批准需求转化为用户可观察、可重复和可判定场景的验收定义。             | 是执行前的定义，不是实际执行结果。                              |
| 验收执行报告 | 只登记实际执行结果、证据和缺陷的记录。                                   | 没有执行证据时状态只能是“尚未执行”，不能由验收用例或计划替代。  |

## 8. 废弃术语与兼容禁令

- 旧拼音 API 名称只可在明确标注的历史证据中出现，不能成为当前契约。
- 旧字段和旧数据库模型不进入新需求，不建立别名或迁移要求。
- “阶段设计 `v1.0`”与“最终需求基线 `v1.0`”是两个不同对象；前者批准工作方式与首轮边界，后者只有在 G5 正式批准后才成立。
- “验收用例”不是“验收执行报告”；没有执行证据时状态只能是“尚未执行”。

## 9. 语言与术语一致性规则

- 用户界面、用户可见提示、需求与验收文档以简体中文为主。
- 同一概念在文档、界面、验收证据和审计结果中使用统一中文术语；必要英文技术词可在首次出现时于括号内保留原文。
- 角色、状态、错误、成功、处理中和拒绝等用户可见状态不得只显示英文代码或内部标识。
- 源代码标识符、日志字段和协议名称可用英文，但面向用户的含义必须有中文解释或映射。
