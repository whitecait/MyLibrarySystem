## 2. 业务目标

**ID:** `MLS-OBJ-0001`

为单一图书馆建立统一、可审计的核心业务系统。

**ID:** `MLS-OBJ-0002`

支持访客、读者、馆员和系统管理员完成首版核心流通目标。

**ID:** `MLS-OBJ-0003`

通过自动判定、人工边界处理和完整审计提高业务处理的一致性与可追责性。

**ID:** `MLS-OBJ-0004`

在不连接任何真实支付网络的前提下演示罚款支付完整闭环。

**ID:** `MLS-OBJ-0005`

通过与业务系统共用数据、业务规则和权限体系的对话式 AI 助手，为参与者提供权限内业务问答与经用户确认的辅助操作。

## 3. 范围摘要

系统服务单一图书馆。首版范围包括账户与权限、读者管理、书目与实体副本、公开检索、借阅、归还、自助续借、逾期罚款、模拟支付、操作审计和对话式 AI 助手。

AI 助手以当前会话角色（访客、读者、馆员或系统管理员）的权限运行，提供权限内业务问答与经用户确认的辅助操作；访客受限开放（仅 L1 级查询并受 AI 调用额度池约束）。AI 对业务行为的参与按四级登记：L1 查询返回、L2 起草确认、L3 页面引导、L4 拒绝；资金三项与高风险四类操作 AI 上限为 L3。账户采用一账户一角色一页面集模型。AI 能力经由系统管理的模型服务端点接口提供，端点兼容本地模型部署与云端 API 两种形态。完整行为边界以[系统用例](MLS-DOC-RA-0009.md)、[功能需求](MLS-DOC-RA-0010.md)和[非功能需求](MLS-DOC-RA-0013.md)的 AI 条目为准。

首版明确排除多馆点或多租户、跨馆调拨、电子资源、预约排队、业务通知、公告、留言、通用上传、统计仪表盘、遗失损坏赔偿、真实支付或官方沙箱、除本地支付模拟器和 AI 模型服务端点之外的外部系统、AI 助手未经用户确认直接执行业务变更，以及旧接口、旧字段、旧数据库的兼容迁移。完整边界以[愿景与范围](MLS-DOC-RA-0004.md)为专题入口。

## 4. 项目约束

**ID:** `MLS-CON-0001`

只允许完全本地支付模拟器，不连接真实平台、官方沙箱或真实支付网络。

**ID:** `MLS-CON-0002`

不保存真实商户号、真实密钥、真实付款凭据或真实付款信息。

**ID:** `MLS-CON-0003`

首版除本地支付模拟器和 AI 模型服务端点外不集成其他外部系统；AI 模型服务端点接口兼容本地模型部署与云端 API 两种形态，形态选择属设计决策。

**ID:** `MLS-CON-0004`

不兼容旧拼音 API、旧字段和旧数据库，不提供兼容迁移。

**ID:** `MLS-CON-0005`

旧文档、旧测试和现有代码均非新需求的规范性来源。
