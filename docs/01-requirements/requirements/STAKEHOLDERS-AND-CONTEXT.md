## 1. 业务参与者

**ID:** `MLS-ACT-0001`

- **名称：** 访客
- **定义：** 未以读者身份参与受限业务的公众访问者。其首版目标是公开检索馆藏，并可发起自助注册；注册成功后成为读者。

**ID:** `MLS-ACT-0002`

- **名称：** 读者
- **定义：** 已注册、可使用读者业务能力的参与者。其首版目标包括查看与自身有关的流通和罚款信息、发起自助续借，以及使用本地模拟支付完成可用的罚款支付演示。

**ID:** `MLS-ACT-0003`

- **名称：** 馆员
- **定义：** 负责日常馆务办理的业务参与者。其首版职责包括读者管理、书目与实体副本管理、借阅和归还办理，以及在授权边界内处理人工例外。

**ID:** `MLS-ACT-0004`

- **名称：** 系统管理员
- **定义：** 负责系统级账户与权限管理、需由更高权限复核的业务事项及审计监督的参与者。哪些高风险人工例外需要其复核仍为 Open 问题。

**ID:** `MLS-ACT-0005`

- **名称：** 本地支付模拟器
- **定义：** 完整验收对象中的受控本地模拟参与方，用于产生成功、失败、取消、超时、重复回调、退款和对账差异等可控业务结果。它不是支付平台、官方沙箱或真实外部网络服务，不连接真实支付网络，不保存真实付款信息，也不产生真实资金交易。

## 2. 利益相关角色

| 角色 | 关注点与责任 |
| --- | --- |
| 项目负责人／需求批准人 | 批准系统范围、业务规则和最终需求基线 |
| 需求负责人 | 维护需求工件、Open 问题和追踪关系 |
| 业务代表 | 从单一图书馆业务角度确认流程、规则和术语 |
| 验收负责人 | 检查需求能否转化为完整系统的验收场景 |
| 架构与开发角色 | 提供可行性、风险和复用意见，不以实现现状替代业务决策 |
| 配置管理员 | 维护文档版本、状态、变更记录和基线标识 |

同一人可以兼任多个角色，但编写、评审和批准责任必须分别记录。

## 3. 完整验收对象

验收对象是完整系统，浏览器前端、后端、新数据库和完全本地的支付模拟器均在完整验收对象中。验收必须基于参与者可观察的端到端业务结果，不得只验证其中一个局部，也不得把计划、验收用例或历史测试当作已经产生的执行证据。

本节确认验收边界，不预设未来子系统、接口、数据存储或部署结构。

## 4. 系统边界内

- 支撑访客、读者、馆员和系统管理员首版目标的账户、馆藏、流通、罚款、模拟支付和操作审计能力。
- “书目 + 实体副本”的馆藏业务粒度，具体实体副本作为流通对象。
- 全馆统一政策下的自动判定、边界项转人工和授权范围内的人工例外。
- 完全本地支付模拟器及其可控的支付业务场景。
- 为完整系统验收所需的浏览器前端、后端和新数据库业务行为。

## 5. 系统边界外

- 真实支付平台、官方支付沙箱、真实支付网络、真实付款凭据和任何真实资金交易。
- 本地支付模拟器之外的外部系统，包括邮件、短信、统一身份认证和外部用户库。
- 多馆点、多租户、跨馆调拨及其他已明确排除的首版能力。
- 旧拼音 API、旧字段、旧数据库及兼容迁移。
- 历史文档、历史测试和现有代码作为新需求的规范性来源。

## 6. 关键交互语境

- 访客通过完整系统公开检索馆藏，并可自助注册成为读者。
- 读者通过完整系统发起自助续借和与自身罚款有关的本地模拟支付目标。
- 馆员发起借阅、归还及授权范围内的人工例外处理。
- 系统管理员履行系统级管理、复核和审计监督职责；未批准的复核边界保持 Open。
- 本地支付模拟器仅在受控本地环境中与系统形成模拟交互；不得向真实支付域名或官方沙箱发起请求。
