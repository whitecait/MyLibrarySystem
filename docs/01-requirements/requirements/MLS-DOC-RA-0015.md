## 1. 容量与负载政策（MLS-OQ-0010）

### 候选基线

- 目标用户账户：最多 1,000 个受控账户，验收数据集至少包含 200 个账户。
- 馆藏规模：最多 10,000 条书目、30,000 册实体副本。
- 累计业务记录：至少覆盖 100,000 条流通、罚款、模拟支付、退款、预约和审计记录的组合数据。
- 峰值并发：50 个并发用户，其中至少 20 个同时执行检索、查看、借阅、续借或支付相关操作。
- 峰值业务负载：连续 10 分钟内每分钟至少 100 个业务请求，且包含不少于 20% 的写操作。

### 验证与准入

使用可重复生成的受控数据集，在完整系统边界内执行混合负载。测试报告必须记录数据集版本、并发模型、场景比例、持续时间、环境标识和失败请求。候选基线要求测试期间无数据丢失、无重复业务事实、无未处理的服务错误；性能阈值由 `MLS-OQ-0011` 共同判定。

## 2. 响应时间政策（MLS-OQ-0011）

### 候选目标

在达到本草案容量基线且不计入人工输入、网络不可控等待和浏览器渲染异常的条件下：

| 场景 | 候选目标 |
| ---- | -------- |
| 公开检索、列表和详情读取 | p95 ≤ 2 秒，p99 ≤ 4 秒 |
| 登录、注册、普通查询和单对象读取 | p95 ≤ 2 秒，p99 ≤ 4 秒 |
| 借阅、归还、续借、预约和罚款操作 | p95 ≤ 3 秒，p99 ≤ 5 秒 |
| 模拟支付结果处理、退款和对账查询 | p95 ≤ 3 秒，p99 ≤ 6 秒 |
| 审计查询和筛选 | p95 ≤ 4 秒，p99 ≤ 8 秒 |

页面从用户提交可识别操作开始计时，到结果可观察且不再显示处理中为止；服务场景从请求发送到响应完整返回计时。所有指定场景至少有效采样 100 次，准入要求为各场景均达到对应 p95 和 p99 目标，且不得以平均值替代分位值。

## 3. 质量、备份恢复与隐私政策（MLS-OQ-0012）

- 安全：不得存在阻断登录、越权访问、真实支付网络调用、真实支付凭据保存或敏感信息越权披露的未关闭严重缺陷；角色边界、审计责任链和支付隔离必须通过验收场景。
- 可用性：受控验收观察窗口为连续 7 个自然日；计划内维护时段除外，业务服务可用率候选目标为至少 99%。
- 备份恢复：受控业务数据的候选恢复点目标为不超过 24 小时，恢复时间目标为不超过 4 小时；恢复后必须能继续执行核心检索、流通、罚款和模拟支付场景。
- 隐私：只使用专用学习数据；验收、日志和执行证据不得包含真实读者、真实支付凭据、真实商户资料或真实付款信息；读者只能访问本人受批准范围内的信息。
- 正式豁免：审计留存期限沿用 `MLS-OQ-0008` 已批准的正式豁免，不在本草案重新定义；其他指标不得以“学习项目”作为默认豁免理由。

## 4. 兼容与无障碍政策（MLS-OQ-0013）

- 浏览器范围：支持桌面端 Chrome、Edge、Firefox 的当前稳定版及前一个稳定大版本；验收使用各浏览器的稳定版本并记录精确版本号。
- 屏幕范围：桌面端 1280×720 至 2560×1440；窄屏端 375×667 至 430×932。不得出现关键操作不可见、不可提交或需要横向滚动才能完成核心流程的情况。
- 键盘操作：公开检索、登录、注册、借阅相关查看、续借、罚款查看和模拟支付提示等核心流程必须可仅用键盘完成；焦点顺序可理解且焦点位置可见。
- 可读性与提示：表单控件具有可理解名称，错误信息与状态变化可识别，模拟支付提示在所有支付交互中保持显著可见；文本与背景对比度候选要求按 WCAG 2.1 AA 检查。
- 验收边界：本项目不承诺原生移动端应用、屏幕阅读器的全部组合或超出上述浏览器与屏幕范围的环境；不在范围内的环境不得被表述为已兼容。

## 5. 验收环境与准入政策（MLS-OQ-0014）

### 环境与数据

- 验收对象是浏览器、前端、后端、数据库和完全本地支付模拟器组成的完整系统。
- 验收环境必须隔离外部支付网络，只使用专用学习数据和可重复建立的数据集。
- 每个执行批次必须固定并记录系统基线、环境标识、浏览器版本、数据集版本、配置版本、执行人和复核人。
- 候选执行准入要求：需求及验收定义已批准，关联 OQ 已关闭或有明确批准延期，环境和数据集通过配置核对，所有用例具备可观察预期结果。

### 缺陷与退出

- Sev-1：阻断核心流程、造成数据破坏、越权、真实支付风险或无法建立可信证据。准入和退出均要求为 0。
- Sev-2：使 Must 需求失败或造成关键业务事实错误。退出要求为 0。
- Sev-3：非核心功能或可替代性问题。退出时不得超过 3 个，且必须有责任人、修复版本和批准的风险接受结论。
- Sev-4：文字、视觉或不影响业务判定的问题。可带缺陷退出，但必须登记并评估对 `MLS-OQ-0015` 和无障碍验收的影响。
- 退出要求：所有 Must 验收用例已执行；阻断项为 0；允许遗留缺陷均已批准；重测和回归范围已完成；证据可由另一名复核者重建；最终结论由需求批准人签署。

## 6. 文档与界面语言政策（MLS-OQ-0015）

- 首选语言：用户界面、用户可见提示、需求和验收文档以简体中文为主。
- 术语规则：同一概念在文档、界面、验收证据和审计结果中使用统一中文术语；首次出现的必要英文技术词可在括号中保留英文原文。
- 标识规则：角色、状态、错误、成功、处理中和拒绝等用户可见状态不得只显示英文代码或内部标识。
- 代码与协议：源代码标识符、日志字段和协议名称可以使用英文，但面向用户的含义必须有中文解释或映射。
- 验收要求：抽查核心流程和全部模拟支付交互，确认无关键中文缺失、同义词混用、未解释英文或仅凭内部 ID 才能理解的结果。
