## 1. 业务参与者

**ID:** `MLS-ACT-0001`

- **名称：** 访客
- **定义：** 未以读者身份参与受限业务的公众访问者。其首版目标包括通过读者页公共门户检索与浏览馆藏（分类筛选、可借状态筛选、可在线阅读筛选、排序、分页与书目详情）、使用公开在线阅读器，并可发起自助注册；注册成功后成为读者。访客作为会话角色可使用 AI 助手以 L1 级查询其现行可见范围内的信息，并受 AI 调用额度池的全局共享池约束（`MLS-DEC-0012`）。

**ID:** `MLS-ACT-0002`

- **名称：** 读者
- **定义：** 已注册、可使用读者业务能力的参与者。其首版目标包括通过"我的业务"查看与自身有关的流通、预约候补、罚款与通知信息，发起预约与候补、自助续借和自助借阅，以及使用本地模拟支付完成可用的罚款支付演示。

**ID:** `MLS-ACT-0003`

- **名称：** 馆员
- **定义：** 负责日常馆务办理的业务参与者。其首版职责包括读者管理、书目与实体副本管理（含副本维护、停用与恢复）、借阅和归还办理，以及在授权边界内处理普通人工例外，并可应读者请求协助重置密码。

**ID:** `MLS-ACT-0004`

- **名称：** 系统管理员
- **定义：** 负责系统级账户与权限管理、账户停用与恢复、密码重置、需由更高权限复核的高风险人工例外及审计监督的参与者。高风险人工例外包括罚款减免或豁免、强制更改流通事实、账户停用/恢复和角色/权限变更（`MLS-OQ-0005` 关闭）。

**ID:** `MLS-ACT-0005`

- **名称：** 本地支付模拟器
- **定义：** 完整验收对象中的受控本地模拟参与方，用于产生成功、失败、取消、超时、重复回调、退款和对账差异等可控业务结果。它不是支付平台、官方沙箱或真实外部网络服务，不连接真实支付网络，不保存真实付款信息，也不产生真实资金交易。

**ID:** `MLS-ACT-0006`

- **名称：** AI 模型服务端点
- **定义：** 完整验收对象中经由端点接口接入的受控模型服务组件，兼容本地模型部署与云端 API 两种形态（形态选择属设计决策）。它不是业务参与者，不拥有独立系统身份；AI 助手的行为一律以当前会话角色（访客、读者、馆员或系统管理员）的权限运行，不直接改变业务事实。

## 2. 利益相关角色

| 角色                   | 关注点与责任                                         |
| ---------------------- | ---------------------------------------------------- |
| 项目负责人／需求批准人 | 批准系统范围、业务规则和最终需求基线                 |
| 需求负责人             | 维护需求工件、Open 问题和追踪关系                    |
| 业务代表               | 从单一图书馆业务角度确认流程、规则和术语             |
| 验收负责人             | 检查需求能否转化为完整系统的验收场景                 |
| 架构与开发角色         | 提供可行性、风险和复用意见，不以实现现状替代业务决策 |
| 配置管理员             | 维护文档版本、状态、变更记录和基线标识               |

同一人可以兼任多个角色，但编写、评审和批准责任必须分别记录。

## 3. 完整验收对象

验收对象是完整系统，浏览器前端、后端、新数据库、完全本地的支付模拟器和系统管理的 AI 模型服务端点均在完整验收对象中。验收必须基于参与者可观察的端到端业务结果，不得只验证其中一个局部，也不得把计划、验收用例或历史测试当作已经产生的执行证据。

本节确认验收边界，不预设未来子系统、接口、数据存储或部署结构。

## 4. 系统边界内

- 支撑访客、读者、馆员和系统管理员首版目标的账户、馆藏、流通、罚款、模拟支付和操作审计能力。
- “书目 + 实体副本”的馆藏业务粒度，具体实体副本作为流通对象。
- 全馆统一政策下的自动判定、边界项转人工和授权范围内的人工例外。
- 完全本地支付模拟器及其可控的支付业务场景。
- 以当前用户身份运行、经模型服务端点接口接入的对话式 AI 助手：权限内业务问答与经用户确认、完整校验的辅助操作。
- 为完整系统验收所需的浏览器前端、后端和新数据库业务行为。

## 5. 系统边界外

- 真实支付平台、官方支付沙箱、真实支付网络、真实付款凭据和任何真实资金交易。
- 除本地支付模拟器和 AI 模型服务端点之外的外部系统，包括邮件、短信、统一身份认证和外部用户库。
- AI 助手未经用户确认直接执行业务变更，或以任何方式绕过前后端校验。
- 多馆点、多租户、跨馆调拨及其他已明确排除的首版能力。
- 旧拼音 API、旧字段、旧数据库及兼容迁移。
- 历史文档、历史测试和现有代码作为新需求的规范性来源。

## 6. 关键交互语境

- 访客通过完整系统公开检索馆藏，并可自助注册成为读者。
- 访客与读者通过读者页公共门户检索浏览馆藏、查看书目级可借状态并使用公开在线阅读器；未登录用户触发预约或本人事务时经登录模态框登录后续行原操作。
- 读者通过完整系统发起自助续借和与自身罚款有关的本地模拟支付目标。
- 馆员发起借阅、归还及授权范围内的人工例外处理。
- 系统管理员履行系统级账户与权限管理、账户停用/恢复、密码重置、高风险人工例外复核和审计监督职责（高风险清单见 `MLS-OQ-0005` 关闭依据）。
- 本地支付模拟器仅在受控本地环境中与系统形成模拟交互；不得向真实支付域名或官方沙箱发起请求。
- 参与者通过 AI 助手以本人角色语境进行业务问答；AI 起草的操作以页面入口卡片呈现，经用户点击跳转后在现行页面确认提交并按现行流程执行，AI 会话日志与操作日志分别留存并以标识关联。
- AI 模型服务端点是系统管理的受控组件，全部 AI 交互经该端点完成；其形态（本地模型部署或云端 API）按设计决策登记。
