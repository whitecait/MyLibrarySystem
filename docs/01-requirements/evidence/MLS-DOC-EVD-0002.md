## 判断边界与证据限制

代码现状不反向定义需求。本台账只为后续设计阶段提供复用候选、弃用项和验证任务，不形成总体设计、详细设计或模块设计结论。处置状态只有 `候选` 或 `弃用`；“候选”仍须在已批准需求基线建立后重新评估。

2026-09-05 `MLS-DEC-0007`（全量重写策略，见 [`MLS-DOC-GOV-0005`](../../00-governance/MLS-DOC-GOV-0005.md)）登记后，本台账处置状态与 [`MLS-DOC-GOV-0006`](../../00-governance/MLS-DOC-GOV-0006.md) 对齐如下：“重构复用候选”仅表示可在重写实现时作为行为线索与对照材料研究，不构成增量修改或就地修补的基础；“直接复用候选”仍限于不携带业务契约的工程骨架与通用工具；“弃用”资产不得进入新实现基线。所有条目最终是否复用，仍以需求基线 v1.0 批准后的逐项重新评估为准。

2026-07-13 对当前 `.codegraph/` 先后执行了覆盖工程骨架、认证、流通、前端旧拼音 API、`library-server/arc`、测试和配置风险的查询，均返回 `No relevant code found`。因此表中的精确路径由当前工作树的只读路径与符号复核补足；“CodeGraph 证据摘要”明确保留未命中事实，不能把后备扫描包装成 CodeGraph 结论。

## 2026-09-10 处置复核

上表为旧实现调查快照，其“当前存在”描述不再表示本轮工作区事实。C4 复核：旧前端 views/api/router、后端 entity/service/repository、安全与旧业务测试已移除；当前只保留工程骨架与基础设施测试。原型仍为被忽略的本地资产，不作为规范性需求来源。旧配置中的 JWT、H2/MySQL 与 Hibernate 自动建表不再用于当前默认配置。保留历史处置结论，未把旧测试改列为验收通过。

## 处置原则

- **直接复用**只适用于不携带业务契约的通用骨架或工具，并仍需验证。
- **重构复用**表示可研究既有实现，不表示当前行为满足新需求。
- **弃用**表示不得进入新实现基线；历史证据仍可保留用于确认清理范围。
- 所有最终决定必须关联已批准需求、明确风险和可复现验证；本文件不批准任何设计方案。
