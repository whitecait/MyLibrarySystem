## V 模型四阶段

需求分析 ↔ 验收测试

总体设计 ↔ 系统测试

详细设计 ↔ 集成测试

模块设计 ↔ 单元测试

四组映射表达设计工件与其验证活动的对应关系，不表示右侧测试已经执行，也不表示尚未开始的设计阶段已有结论。

### 需求分析 ↔ 验收测试

- 准入：治理入口、编号、状态、权威、变更和归档规则可用，历史资料已降级为非规范性参考。
- 活动：定义系统目标、边界、参与者、业务行为、质量要求、验收条件和追踪关系，不预设实现设计。
- 退出：G1 至 G5 通过，关键问题按门禁要求关闭或获准延期，需求基线由明确评审记录批准。
- 验证：验收测试依据批准的需求基线验证完整系统；当前尚未执行。

### 总体设计 ↔ 系统测试

- 准入：G5 通过，批准的需求基线成为正式输入。
- 活动：定义系统级结构、职责与接口边界，并建立系统测试设计；不得反向改写需求，变更必须受控。
- 退出：总体设计经评审批准，需求到总体设计及系统测试的追踪完整，进入详细设计的输入明确。
- 当前约束：只建入口，不写结论。

### 详细设计 ↔ 集成测试

- 准入：批准的总体设计及其受控需求追踪可用。
- 活动：细化构件、接口、数据与协作关系，并建立集成测试设计。
- 退出：详细设计经评审批准，接口与协作风险已处理，需求、总体设计、详细设计和集成测试可双向追踪。
- 当前约束：只建入口，不写结论。

### 模块设计 ↔ 单元测试

- 准入：批准的详细设计及其受控接口契约可用。
- 活动：定义模块、类、函数、组件及内部逻辑，并建立单元测试设计。
- 退出：模块设计经评审批准，模块职责和单元验证覆盖可追踪，批准输入具备实施条件。
- 当前约束：只建入口，不写结论。

后三阶段当前只建入口，不写结论。

## 工作包

| 工作包          | 目标                                         | 主要交付                     | 对应门禁 |
| --------------- | -------------------------------------------- | ---------------------------- | -------- |
| WP-0 治理就绪   | 建立可跟踪、可评审、可归档的文档权威链       | 唯一入口、治理规则、归档索引 | G0       |
| WP-1 范围定义   | 明确目标、参与者、系统边界、范围和术语       | 系统范围工件                 | G1       |
| WP-2 业务分析   | 明确流程、用例、功能需求、业务规则和概念信息 | 业务需求包                   | G2       |
| WP-3 质量与验收 | 建立可测量质量要求、验收定义和双向追踪       | 可验收需求包                 | G3、G4   |
| WP-4 基线批准   | 完成一致性检查、问题处置、评审和版本冻结     | 经批准的需求基线             | G5       |

## 门禁 G0 至 G5

| 门禁            | 准入                                             | 退出条件                                                                                     |
| --------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| G0 治理就绪     | 已批准的需求分析阶段组织与工作基线可用           | `docs/` 可跟踪；唯一入口、模板、编号、状态、权威和变更规则可用；旧资料已归档且明确为非规范性 |
| G1 范围评审     | G0 通过;范围工件具备评审条件                     | 系统目标、参与者、范围内外和外部参与方明确；所有 P0 范围问题关闭                             |
| G2 业务评审     | G1 通过;业务需求包具备评审条件                   | 核心及异常流程、用例、功能需求和业务规则之间无关键冲突                                       |
| G3 需求质量评审 | G2 通过;质量与验收工件具备评审条件               | 所有 Must 需求原子化、无歧义、必要、可行且可验证，不含未批准设计结论                         |
| G4 验收就绪评审 | G3 通过;验收条件、验收用例和追踪关系具备评审条件 | 每项 Must 需求具有验收条件和验收用例；非功能需求有量化阈值或正式批准的豁免                   |
| G5 基线批准     | G4 通过;评审材料和问题处置记录完整               | 追踪矩阵无孤立项；评审问题已关闭或经批准延期；批准人和结论明确；需求基线正式发布为 `v1.0`    |

门禁结论必须由评审记录支持。文档提交、链接建立或静态检查通过均不等于门禁批准。
