# 编号规范

| 字段     | 值                                     |
| -------- | -------------------------------------- |
| 文档编号 | `MLS-DOC-GOV-0001`                     |
| 文档状态 | `Draft`                                |
| 文档版本 | `v0.1`                                 |
| 编制日期 | `2026-07-23`                           |
| 适用阶段 | 全生命周期治理；当前处于需求分析       |
| 验证对应 | 评审与基线控制                         |
| 权威性质 | 规范性；定义工程中所有编号的格式与规则 |

## 1. 范围

本文件是 MyLibrarySystem 工程中所有编号的统一规范来源。涵盖以下三类编号：

- **文档编号** (`MLS-DOC-*`)：规范性与证据性文档本身的标识
- **工件编号** (`MLS-OBJ-*`、`MLS-FR-*` 等)：需求工件、验收工件和评审工件的标识
- **决策编号** (`MLS-DEC-*`)：工程决策记录的标识

本文件不定义目录结构、文件组织或命名之外的文档内容规则。

## 2. 文档编号

### 2.1 格式

```
MLS-DOC-{阶段}-{序号}
```

| 段     | 规则                     | 示例   |
| ------ | ------------------------ | ------ |
| 前缀   | 固定 `MLS-DOC`           |        |
| 阶段   | 两位大写字母，按阶段分配 | `GOV`  |
| 序号   | 四位零填充数字           | `0001` |

### 2.2 阶段缩写

| 缩写  | 阶段或职能     | 对应目录               | 分配范围     |
| ----- | -------------- | ---------------------- | ------------ |
| `GOV` | 治理框架       | `docs/`、`00-governance/` | `0000`–`0999` |
| `RA`  | 需求分析       | `docs/01-requirements/`  | `0001`–`0999` |
| `AT`  | 验收测试       | `docs/01-requirements/acceptance/` | `0001`–`0999` |
| `EVD` | 证据           | `docs/01-requirements/evidence/`   | `0001`–`0999` |
| `REV` | 评审           | `docs/01-requirements/reviews/`    | `0001`–`0999` |
| `OD`  | 总体设计       | `docs/02-overall-design/`          | `0001`–`0999` |
| `DD`  | 详细设计       | `docs/03-detailed-design/`         | `0001`–`0999` |
| `MD`  | 模块设计       | `docs/04-module-design/`           | `0001`–`0999` |
| `ARC` | 归档           | `docs/90-archive/`                 | `0001`–`0999` |

### 2.3 分配规则

- 序号在各阶段缩写内顺序递增。
- `MLS-DOC-GOV-0000` 保留给工程文档唯一入口 [`docs/README.md`](../README.md)。
- 编号一经分配永久保留。废弃的编号改为 `Retired` 并在变更记录中说明原因，不得删除后复用。
- 新文档创建前必须在本规范的分配记录中登记，确保不与其他已分配或预留编号冲突。

## 3. 工件编号

### 3.1 格式

工件编号格式为 `MLS-{类型}-{序号}` 或 `MLS-{类型}-{类别}-{序号}`。编号不得包含可能变化的子系统名称。

### 3.2 类型表

| 工件       | 编号格式               | 示例                | 说明                   |
| ---------- | ---------------------- | ------------------- | ---------------------- |
| 业务目标   | `MLS-OBJ-NNNN`         | `MLS-OBJ-0001`      |                        |
| 参与者     | `MLS-ACT-NNNN`         | `MLS-ACT-0001`      |                        |
| 用例       | `MLS-UC-NNNN`          | `MLS-UC-0001`       |                        |
| 功能需求   | `MLS-FR-NNNN`          | `MLS-FR-0001`       |                        |
| 业务规则   | `MLS-BR-NNNN`          | `MLS-BR-0001`       |                        |
| 信息需求   | `MLS-IR-NNNN`          | `MLS-IR-0001`       |                        |
| 非功能需求 | `MLS-NFR-{类别}-NNNN`  | `MLS-NFR-SEC-0001`  | 类别见 3.3             |
| 项目约束   | `MLS-CON-NNNN`         | `MLS-CON-0001`      |                        |
| 验收条件   | `MLS-AC-NNNN`          | `MLS-AC-0001`       |                        |
| 验收用例   | `MLS-AT-NNNN`          | `MLS-AT-0001`       |                        |
| Open 问题  | `MLS-OQ-NNNN`          | `MLS-OQ-0001`       |                        |

### 3.3 NFR 类别缩写

| 缩写  | 类别       |
| ----- | ---------- |
| `SEC` | 安全       |
| `REL` | 可靠性     |
| `PER` | 性能       |
| `USE` | 可用性     |
| `AVL` | 可恢复性   |
| `CMP` | 兼容性     |
| `AUD` | 可审计性   |

NFR 类别缩写可根据后续阶段需要扩展，扩展时必须在本文件中登记并记录依据。

## 4. 决策编号

| 类型   | 编号格式         | 示例            |
| ------ | ---------------- | --------------- |
| 决策   | `MLS-DEC-NNNN`   | `MLS-DEC-0001`  |

决策编号在 [`MLS-DOC-GOV-0005.md`](MLS-DOC-GOV-0005.md) 中分配与管理。每条决策记录必须引用明确的来源工件和评审结论。

## 5. 通用规则

### 5.1 永久性

所有编号一经分配即永久保留。即使对应工件被废弃、替换或合并，编号不得删除或分配给其他含义。

### 5.2 退役

废弃工件不删除，其编号改为 `Retired` 状态，并在对应变更记录中保留：

- 退役原因
- 替代工件编号（如适用）
- 退役日期和批准人

### 5.3 序号

序号均从 `0001` 起，按分配时间顺序递增。不得为表达层级关系而使用非连续编号。

### 5.4 稳定性

编号不得包含可能变化的子系统名称、技术栈名称或组织名称。编号独立于文件路径、标题和内容——即使文件被重命名或移至其他目录，编号保持不变。
