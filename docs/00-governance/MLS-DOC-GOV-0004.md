## 状态流

受控工件和受控条目的状态固定为：`Draft → In Review → Approved → Changed/Retired`。

| 状态      | 含义                                                             |
| --------- | ---------------------------------------------------------------- |
| Draft     | 正在编制，不能作为已批准基线或后续阶段正式输入                   |
| In Review | 已提交评审，评审尚未形成批准结论                                 |
| Approved  | 已有明确评审人、批准人、日期和结论，可以在适用范围内作为正式输入 |
| Changed   | 原批准内容经受控变更被新批准版本替代，历史记录继续保留           |
| Retired   | 工件或条目退出当前适用范围，保留标识、原因和替代关系             |

提交不等于批准。Git 提交、合并、链接建立、格式检查或测试通过均不能代替正式评审与批准记录。

## 标识与版本

- ID 永不复用。已分配 ID 即使被变更或退役也必须保留，禁止删除后分配给其他含义。
- 新建规范性文档从 `Draft`、`v0.1` 开始；进入评审不自动改变批准状态。
- 版本变更必须与变更记录和批准结论对应。只有评审记录明确批准后，工件才能标记为 `Approved`。
- 已批准内容发生变化时，旧版本保留追溯关系，新版本在完成影响分析和重新评审前不得冒充批准基线。
- 纯编辑性同步（无内容事实变化，如链接修复、格式修正或引用列表补充）在变更记录中记「不变」版本行，不升版本号；内容事实变化必须升版本号并对应批准结论。

## 变更流程

1. 提出变更并分配稳定标识；说明变更原因和期望结果。
2. 识别受影响需求、验收定义、追踪关系、评审记录和后续阶段输入。
3. 由评审人核对一致性、可验证性、设计泄漏和风险。
4. 由批准人记录批准、拒绝、退回或延期结论。
5. 仅在批准后更新规范性工件状态、版本和追踪关系；保留旧结论和替代关系。

## 变更记录必备字段

每条变更记录必须包含以下字段，不得省略：

- 原因
- 提出人
- 日期
- 影响需求
- 影响验收
- 评审人
- 批准人
- 结论

若某字段暂时未知，应将变更保持在 `Draft` 或 `In Review`，不得虚构责任人、日期、业务数值或批准结论。
