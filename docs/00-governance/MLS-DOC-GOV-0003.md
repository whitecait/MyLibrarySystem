## 分层权威模型

工程文档采用分层职责模型，不用一条箭头同时表达导航、内容所有权和批准效力。完整入口和阅读顺序由 [`docs/README.md`](../README.md) 维护。

| 层级          | 工件                                                                         | 职责                                                 | 是否产生需求事实                   |
| ------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------- |
| L0 入口与导航 | `MLS-DOC-GOV-0000`                                                           | 声明当前阶段、维护清单和阅读入口                     | 否                                 |
| L1 治理规则   | `MLS-DOC-GOV-0001` 至 `MLS-DOC-GOV-0007` | 分别定义编号、生命周期与门禁、权威与冲突、变更、决策、全局开发计划和风险登记 | 否                                 |
| L2 阶段控制   | `MLS-DOC-RA-0001`、`MLS-DOC-RA-0002`                                         | 定义需求分析阶段组织基线和阶段导航                   | 只定义阶段边界与工作方式           |
| L3 规范内容   | `MLS-DOC-RA-0003` 至 `MLS-DOC-RA-0013`、`MLS-DOC-AT-0001`、`MLS-DOC-AT-0002` | 定义需求与验收事实                                   | 是；仅 Approved 版本可进入正式基线 |
| L4 控制与批准 | `MLS-DOC-RA-0014`、`MLS-DOC-REV-0001`、`MLS-DOC-REV-0002`                    | 维护派生追踪、评审证据和基线激活记录                 | 否                                 |
| 支持材料      | `MLS-DOC-AT-0003`、`evidence/`                                               | 保存执行、分析和历史证据                             | 否                                 |

层级只表达职责依赖，不表达“层级数字越小或越大就自动覆盖其他层”。批准状态、内容所有权和基线记录共同决定实际效力。

当前 `MLS-DOC-RA-0001 v1.0` 的已批准正文仍保留早期目标目录和箭头式权威关系。G0 治理重评审已于 2026-07-24 通过（分层模型自洽、编号一致、无治理越权、链接完整），本分层模型作为当前维护与评审导航；该批准版本的旧目录与箭头式权威仍作为历史批准内容保留，本模型不得宣称已经覆盖或静默改写它。

## 治理主题所有权

L1 治理文件相互并列，并在各自主题内拥有唯一内容所有权：

| 治理主题                         | 所有者                                       |
| -------------------------------- | -------------------------------------------- |
| 文档与工件编号                   | [`MLS-DOC-GOV-0001.md`](MLS-DOC-GOV-0001.md) |
| 生命周期、工作包、准入退出和门禁 | [`MLS-DOC-GOV-0002.md`](MLS-DOC-GOV-0002.md) |
| 权威层级、内容所有权和冲突处理   | 本文件                                       |
| 状态、版本和变更评审             | [`MLS-DOC-GOV-0004.md`](MLS-DOC-GOV-0004.md) |
| 工程决策登记                     | [`MLS-DOC-GOV-0005.md`](MLS-DOC-GOV-0005.md) |
| 全局开发计划                     | [`MLS-DOC-GOV-0006.md`](MLS-DOC-GOV-0006.md) |
| 风险登记                         | [`MLS-DOC-GOV-0007.md`](MLS-DOC-GOV-0007.md) |

某治理文件不得在正文中重新定义其他治理主题。发生跨主题冲突时，必须同时引用相关所有者并按变更控制形成统一结论。

## 规范内容所有权

1. [`MLS-DOC-RA-0003.md`](../01-requirements/requirements/MLS-DOC-RA-0003.md)维护系统级目标、范围、约束、当前基线状态和专题导航。
2. [`MLS-DOC-RA-0004.md`](../01-requirements/requirements/MLS-DOC-RA-0004.md)至[`MLS-DOC-RA-0013.md`](../01-requirements/requirements/MLS-DOC-RA-0013.md)分别维护其标题所对应的专题详细事实。主规格只保留必要汇总；专题事实变更时必须同步更新主规格摘要。
3. [`MLS-DOC-AT-0001.md`](../01-requirements/acceptance/MLS-DOC-AT-0001.md)维护验收策略，[`MLS-DOC-AT-0002.md`](../01-requirements/acceptance/MLS-DOC-AT-0002.md)维护验收条件和验收用例。
4. [`MLS-DOC-RA-0014.md`](../01-requirements/requirements/MLS-DOC-RA-0014.md)是从来源工件派生的追踪索引，不拥有需求或验收事实。矩阵与来源不一致时必须修正矩阵。
5. [`MLS-DOC-REV-0002.md`](../01-requirements/reviews/MLS-DOC-REV-0002.md)记录某次需求基线包含的精确工件 ID、版本、批准人、日期和结论。它只激活已评审内容，不创建或改写需求。

## 工件性质与基线激活

| 类别   | 目录或工件                                          | 规则                                                       |
| ------ | --------------------------------------------------- | ---------------------------------------------------------- |
| 规范性 | L3 中的主规格、专题需求和验收定义                   | 只有被基线记录按明确版本批准后，才可作为后续阶段正式输入   |
| 控制性 | L0、L1、L2、L4                                      | 定义治理、导航、追踪和批准证据；不得借控制记录新增需求事实 |
| 证据性 | `docs/01-requirements/evidence/`、`MLS-DOC-AT-0003` | 非规范性；只记录分析或实际执行证据                         |

需求基线只有在 `MLS-DOC-REV-0002` 完整列出候选集合，并具备明确评审人、批准人、日期和批准结论后才被激活。部分文档单独标记为 Approved、Git 提交、链接建立或静态检查通过，均不能替代基线激活记录。

## 冲突处理

当工件之间出现冲突时：

1. 先按本文件识别冲突内容的唯一所有者；派生索引、导航摘要和证据不得覆盖来源工件。
2. 在同一内容所有权范围内，以 `MLS-DOC-REV-0002` 所登记的最后批准版本为准。
3. 若冲突工件均未进入已批准基线，保持“未建立基线”或“冲突未解决”，不得任意选择 Draft 内容。
4. 标识冲突项、各自版本、状态、批准记录，以及受影响的需求、验收定义、追踪关系和后续阶段输入。
5. 按[变更控制](MLS-DOC-GOV-0004.md)开展影响分析、评审和批准，并在结论批准后同步更新所有受影响工件。
6. 不删除历史 ID、旧版本或批准记录。

Draft、In Review 或仅已提交的内容不得覆盖最后批准的规范性工件。`evidence/` 与 `MLS-DOC-AT-0003` 可以支持分析，但不能单独批准或覆盖规范性要求。
