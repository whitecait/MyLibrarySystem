## 1. 事务边界（跨事务时序的提交边界）

| 业务链 | 事务范围（同一数据库事务） | 事务外 | 依据 |
| --- | --- | --- | --- |
| 归还 | 借阅结束＋副本迁移＋罚款形成＋Outbox 登记 | 审计失败记录（独立事务）；异步投递 | SC-Q2 |
| 预约/候补 | 事务建立＋绑定或入队（原子）＋Outbox | 候补确认前的展示（无事实） | RS-D4/D6 |
| 取书借出 | 借出＋副本 LENT＋Outbox | — | PK-D4 |
| 闭馆批次 | 未到馆处理＋清点＋结算三阶段＋本轮事件 | 失败诊断/审计（独立事务）；重试调度 | SC-Q5 |
| 复核批准 | 批准记录＋目标受控变更＋Outbox | 失败审计（独立事务） | SC-Q9/RV-D4 |
| 订单关闭 | 关闭事实＋占用释放（同事务原子） | 失败日志 | SC-Q15/D3/D12 |
| 支付成功 | 结算＋订单 PAID＋占用释放＋Outbox | 退款流程（独立业务） | SC-Q15/D5 |

规则：任何"业务事实＋事件"必须同事务；失败审计永远独立提交（不随业务回滚丢弃）；用户等待路径不含异步投递（AT-0002 既有口径）。

## 2. 条件更新（CAS）与冲突结果规则

- 全部状态迁移＝条件更新：`UPDATE t SET state=:next, version=version+1, updated_at=now() WHERE id=:id AND state=:expected AND version=:version`；影响行数 0 → 返回 `MLS-CIRC-003`/相应冲突码（携带当前最新状态摘要），**不自动重试业务判定**；客户端按 BR-0045 以最新状态重新确认（AT-0015/AT-0030 口径）。
- 终态封闭由迁移白名单（应用层迁移表＋无以终态为源的迁移）保证，越终态写入即条件更新失败。
- 建单独占：条件插入依赖 `uq_payment_order_unreleased`（DD-0003），冲突返回 `MLS-PAY-001`。

## 3. 统一锁序与死锁预防

固定获取顺序：闭馆控制 →（书目）预约队列 → 借阅事务 → 副本 → 罚款/订单 → Outbox；同层按主键字典序。实现约束：

- 用例编排按上序访问；行锁来自条件更新与 `SELECT ... FOR UPDATE`（仅显式需要多读一致时使用，按同序）。
- 锁等待超时 3s（`lock_timeout`）；超时＝确定失败，按冲突结果规则返回，不做隐式重试。
- 用户可见路径无自动重试（错误即返回）；后台闭馆重试为有限次（默认 1 次，配置 `closing.retry-budget`）、固定原业务日（SC-Q7/Q8）。

## 4. 严格 T 截止实现与证明链

**方案**：闭馆开始时先行提交控制状态迁移 `closing_control: OPEN→ISOLATED`（带 `current_date`）；此后一切普通业务写用例在事务首条语句读取控制状态（同一事务内快照），`ISOLATED` 即拒绝（RS-D1/PK-D1/RT-D1 对应错误码）；闭馆批次成功后按路径恢复 `ISOLATED→REOPENED`（正常路径自动，逐日补结路径经管理员开放，DD-0002 §2.5）。

**为何满足 SC-Q3（严格提交截止而非准入截止）**：判定发生在写事务内部对控制状态的读取处——T 之后开始的事务读到 ISOLATED 即失败；T 之前开始但 T 时尚未提交的事务，其快照早于 ISOLATED 提交，按 PostgreSQL 提交序其写入的可见性与闭馆取数互斥（闭馆取数事务在 ISOLATED 提交之后开始，看不到未提交写入），未提交者在提交时与闭馆串行化冲突由行锁/串行化保证回退。不以请求开始时间、网络到达或准入时间为判据。

**证明链**：① 业务规则 BR-0046（外部行为，枚举 T 前提交/T 时未提交/隔离请求三结局）；② TLA+ `Closing.tla` 模型检测（480 状态穷举：隔离期冻结不变量 InvFreeze、后日不越序 InvOrder、开放门控 InvReopenGated 全部成立；恢复出口五探针可达）；③ 本文事务级实现方案（控制状态门控＋读写冲突串行化）；④ 可执行验证＝DD-0006 场景 C1~C3（注入式）。四层证据闭合，结论：严格 T 截止方案可实现且可验证。

## 5. 异常、冲突与恢复行为汇总（可执行规则）

| 情形 | 结果/返回 | 重试 | 恢复 |
| --- | --- | --- | --- |
| CAS 影响 0 行 | 冲突码＋最新状态摘要 | 不自动 | 客户端按最新状态重新确认 |
| 建单撞占用 | `MLS-PAY-001` | 不自动 | 按原订单继续办理 |
| 锁等待超时 | 冲突码（同 CAS） | 不自动（用户路径） | 重新提交 |
| 闭馆批次失败 | 当日整体回滚＋独立审计 | 后台有限次（原日期） | 耗尽转人工；管理员开放（DD-0002 §2.5） |
| 支付尝试超时 | 仅日志，订单不变（D2） | 用户主动再次支付 | — |
| 关闭执行失败 | `MLS-PAY-004`，占用保持（D4） | 用户/系统再发起 | — |
| 迟到事件到终态 | 仅日志（D15 吸收） | — | — |
| 进程崩溃于事务中 | 数据库原子回滚 | — | 重启后按最新事实继续；Outbox 未提交事件随事务消失，已提交事件至少一次投递 |
