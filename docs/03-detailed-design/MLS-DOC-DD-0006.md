## 1. 定位与执行环境

本文把 OD-0004 §5 拆出的并发/恢复场景定到步骤级（可执行）。执行环境＝OD-0004 §4（E 规格、真实 PostgreSQL、独立实例）；注入方式＝DD-0005 §3。命名约定：场景 C*=闭馆族、P*=订单族、X*=并发族、R*=恢复族；断言锚点＝BR-0039~0048 逐条。执行时点 M5（随实现），本文不登记已执行结论。

## 2. 场景规格（步骤级）

### C1 T 前提交纳入（BR-0046/CL-D1）

1. 装载：已确认预约（当日）＋在途归还请求 R0。
2. R0 开始事务→注入延迟→闭馆触发前 200ms 提交。
3. 断言：R0 结果成功；闭馆取数快照含 R0 事实；批次三阶段成功；控制状态 REOPENED。

### C2 T 时未提交失败回滚（CL-D2）

1. R0 开始事务→注入 `commit-crash`（提交前挂起）→闭馆触发（控制状态 ISOLATED）→放行 R0 提交。
2. 断言：R0 冲突失败（`MLS-CIRC-002`）回滚无残留；闭馆取数不含 R0；重放同请求不并入本轮（不可补交）。

### C3 隔离期新请求明确失败（CL-D3）；C4 闭馆失败与重试（CL-D5/D6）

隔离窗口内提交预约/归还/借出→断言明确失败＋审计。注入 `closing-fail`：断言当日整体回滚、独立审计存在、自动重试按原 business_date；耗尽后批次 MANUAL、保持 ISOLATED。

### C5 逐日补结与管理员开放（CL-D8~D11）

构造 d1 成功、d2 失败两批：断言 d1 不回滚、d2 重试至成功→追平后仍 ISOLATED→`POST /closing/reopen`（ADMIN）成功→REOPENED；越权/未追平变体断言拒绝。

### P1 建单独占与继任（BR-0047/D7~D9/D12~D14）

并发两请求为同罚款建单（`Idempotency-Key` 不同）：断言恰一成功、另一 `MLS-PAY-001`；成功者支付→PAID→结清→再建单 `MLS-PAY-002`；变体：CLOSED 后继任可建。

### P2 超时/关闭失败不释放（D2/D4/D13）

模拟器超时回调→订单仍 OCCUPIED、仅日志；`close` 注入失败→`MLS-PAY-004`、仍占用。

### P3 终态吸收（D15/D6/D5）

对 PAID 订单注入迟到超时与关闭请求→仅日志、事实不变、登记退款处理（D6）；对 PAID 重复通知→返回首次结果不重复结算（D5）。

### X1 副本竞争（BR-0039/0040/0041）

两请求竞争同一 SHELF_READY 副本（预约确认路径）：断言恰一绑定；多请求竞争末副本：断言成功数≤副本数；队首取消与分配竞争：断言队首不被静默越过或跳过留痕。

### X2 幂等键并发（BR-0042）

同 `Idempotency-Key` 两并发预约：断言仅一次业务效果、两响应一致（首次结果）。

### X3 展示与提交之间变更（BR-0045）

读取日历/可借展示→外部变更书目状态→按陈旧展示提交：断言冲突返回＋最新状态摘要，可重新确认。

### R1 提交中断恢复（DD-0004 §5 崩溃行）

业务提交中注入 `commit-crash`→重启→断言无半完成结果、无重复事实、流程可继续；Outbox 已提交事件仍投递恰一次业务效果。

## 3. 断言→规则→追踪

每场景断言逐条绑定 BR-0039~0048（X 族）、BR-0046（C 族）、BR-0047（P 族）、BR-0048（R1 复核变体并入 X 族扩展）；追踪：`RA-0014` 既有 `MLS-AT-0030` 行已双向覆盖本场景组（需求↔AC-0049↔AT-0030），ODV 新增 BR-0046~0048 行（AT-0031~0033）覆盖 C/P/X 对应用例——双向追踪经既有与新增行闭合，无孤立断言。

## 4. 实现形态

测试代码驻 `library-server/src/test/java/com/library/integration/`（M5 随实现落地）；并发交错以脚本化调用＋注入接口控制，不依赖 UI 时序；每场景输出时间线＋审计导出＋断言查询三件套证据（OD-0004 §4 可复现性）。
